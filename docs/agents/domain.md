# Domain docs

Before exploring an area of Rank It, read the root `GLOSSARY.md` and any relevant architecture decision records in `docs/adr/`. If either is absent, continue with the task. The domain-modeling skill creates these records as terms and decisions are settled.

Use the glossary’s terms in issues, proposals, tests, and code. When a concept is missing, check whether an existing term covers it and flag genuine gaps for domain modeling.

If a proposal conflicts with a recorded decision, identify the ADR and explain why the decision warrants another look.
